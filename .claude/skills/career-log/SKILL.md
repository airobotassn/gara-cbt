# career-log — 작업을 커리어 자산으로 정리

회사 업무를 하면서 **내 커리어에 남길 만한 것**(배운 기술, 해결한 문제, 판단한 근거, 만든 성과)을 한국어 텍스트로 정리해 `docs/커리어기록.md` 한 파일에 계속 쌓는다.

## 재료를 어디서 가져오나

기본은 **지금 대화/작업 세션**이다. 방금 사용자와 함께 한 작업(이번 세션의 도구 호출, 만든 파일, 내린 결정, 발생한 문제와 해결)을 재료로 삼는다.

사용자가 범위를 따로 지정하면 그걸 따른다:
- "최근 커밋들로 정리해줘" → `git log --oneline -20` 등으로 최근 커밋을 훑어 재료로 사용.
- "이런 거 했어 …"라고 말로 설명 → 그 설명을 구조화. (회의·기획 등 코드 외 업무도 포함.)

## 무엇을 뽑나

세션을 훑어 아래를 추린다. **실제로 이번 작업에서 일어난 것만** 적는다 — 추측·과장·없는 성과 만들기 금지. 재료가 빈약하면 솔직하게 "이번 세션엔 기록할 커리어 포인트가 적다"고 말하고 억지로 채우지 않는다.

- **기술/도구**: 새로 쓰거나 깊이 다룬 기술·도구·서비스 (예: Netlify CLI 배포, Supabase RLS, Vite 빌드).
- **문제해결**: 막혔던 지점과 어떻게 풀었는지 (예: GCM 인증이 백그라운드에서 막혀 캐시 후 재시도로 우회).
- **의사결정 & 근거**: 대안을 두고 왜 그 선택을 했는지. **ADR 수준으로 상세히 — 문제 → 검토한 대안 → 결정 → 근거 → 트레이드오프**까지 다 적는다(요약·축약·생략 금지). 이게 나중에 이력서/면접용으로 다시 뽑아낼 **추출 재료**이므로, 대충 적으면 정작 뽑을 소스가 없어진다.
- **정량 성과**: 숫자로 말할 수 있는 것 (배포 시간, 빌드 7.2s, 검증한 테이블 6개 등). 없으면 생략.
- **전이 역량**: 회사·스택을 바꿔도 통하는 일반 역량 (보안 검증 습관, 배포 자동화, 인증 트러블슈팅 등).

## 출력 형식

**읽기 쉬운 텍스트**로 쓰되, **설계 결정·문제해결 같은 핵심은 ADR 수준으로 충분히 상세하게** 적는다(짧게 줄이지 말 것 — 디테일이 곧 나중에 뽑을 추출 재료다). 항목 하나는 아래 골격을 따르되, 빈 칸은 억지로 채우지 말고 자연스럽게 생략한다. 날짜는 환경의 현재 날짜를 쓴다(모르면 사용자에게 묻거나 `git log -1 --format=%cs`로 추정).

```
## YYYY-MM-DD · <한 줄 제목: 무엇을 했나>

**한 일.** 2~3문장으로 무엇을 왜 했는지.

**커리어 포인트.**
- 기술/도구: …
- 문제해결: …
- 의사결정: … (근거 한 줄)
- 정량 성과: …
- 전이 역량: …

**이력서 한 줄.** "<동사로 시작하는 성과 중심 한 줄. 가능하면 숫자 포함>"

**면접 한마디(STAR).** 상황-과제-행동-결과를 2~3문장으로 압축.
```

여러 갈래의 일을 했으면 항목을 여러 개로 나눠도 된다.

## 저장 위치 & 누적 규칙

1. 파일은 항상 `docs/커리어기록.md` **하나**로 통일한다.
2. 파일이 없으면 아래 헤더로 새로 만든다:
   ```
   # 커리어 기록 — <프로젝트/회사명>

   > 회사 업무에서 내 커리어에 남길 만한 것(배운 기술·해결한 문제·판단 근거·성과)을 날짜순으로 쌓는다.
   > 집에서 이력서/브래그 닥/면접 준비에 재활용하기 위한 개인 기록.

   ---
   ```
3. 파일이 있으면 **맨 아래에 새 항목을 append**한다. 기존 내용을 절대 지우거나 고치지 않는다. 항목 사이는 `---`로 구분.
4. 같은 날 추가 작업이면 그날 항목 아래에 이어 붙이거나 새 항목으로 분리 — 자연스러운 쪽으로.

## 마무리 (항상 짧게 보고)

저장 후 사용자에게 **반드시 간략히 요약**한다. 길게 늘어놓지 말고 3~5줄 정도로:
- 추가한 **항목 제목**(날짜 · 한 줄 제목).
- 그 안에 담은 **커리어 포인트 핵심**을 불릿 2~4개로 (예: "기술: Netlify CLI 배포 / 성과: 번들 40%↓ / 전이역량: 위협 모델링").
- 뽑은 **이력서 한 줄**을 그대로 한 번 보여준다.
- 마지막에 `docs/커리어기록.md` 경로.

전문을 다시 출력하지는 않는다 — 파일에 있으니 "뭘 적었는지"만 빠르게 훑게 해준다.

회사 repo에 개인 커리어 기록을 커밋하는 게 부담되면 `.gitignore`에 `docs/커리어기록.md`를 추가해 로컬에만 두는 선택지가 있다고 **한 번** 안내한다(이미 안내했으면 반복하지 않음).
