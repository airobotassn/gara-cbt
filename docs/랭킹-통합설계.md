# 랭킹 통합 재설계 (확정본)

> 작성 맥락: 기존 랭킹이 3세대(CARIS ARENA 개인 명예의전당 → Phase1 집계 협력형 → Phase2 월드아레나 프로토타입)가 위계·용어 통일 없이 축적돼 "짬뽕" 상태. 이를 **하나의 통합 랭킹**으로 정리하는 설계. 이 문서는 결정 사항만 담고, 정확한 수치 튜닝은 구현 후 데이터로 조정한다.

---

## 0. 진단 — 현재 "짬뽕"의 실체 (코드 근거)

1. **정반대 패러다임 공존**: 개인 경쟁(명예의전당, `global_top`, `points desc`) vs 집단 협력(지역/국가/학교 버킷, 익명, "우리가 올라간다") — 위계 선언 없이 `/ranking` 4탭.
2. **메트릭 불일치**: 개인=랭킹점수(`computePoints`, 연속), 집계=`avg(user_progress.rank)`(레벨 평균, 이산). "순위" 기준이 표면마다 다름.
3. **"points" 이름 충돌**: `user_progress.points`(랭킹점수 = Hub "경험치") vs `user_currency.points`(가챠 코인). `get-hub`가 둘 다 내려줌.
4. **시즌이 이름뿐**: `leaderboard` window=season 은 리셋/아카이브 없이 `avg_level`. 개인 보드는 window 자체가 없음(항상 전체).
5. **표면 중복 + 데드 코드**: 집계 탭 ↔ 월드아레나 지구본 동일 데이터 2곳. 루트 `지구본-디자인.html`(682KB, src 미참조) 방치. `rank.lv_rank`/`rank.lv_top` "리그" i18n 키만 존재.

## 1. 목표 & 원칙

- **하나의 통합 랭킹**으로 정리. 개인 경쟁이 메인, 집단 협력은 부가 렌즈.
- **티어 = 상위 정체성**(백분위 밴드). **레벨(1~7) = 티어를 올리는 연료**(유지).
- **시즌 총점 = 실력점수 + 활동점수** → **백분위로 티어**. **점수 상한 없음.**
- **활동 = 바닥 엔진**(성실하면 실력 낮아도 중상위), **천장 = 실력**(최상위는 실력 필요). 이는 **인위적 캡이 아니라 구조로** 달성.

## 2. 점수 모델

### 2.1 실력점수 (레벨테스트 · 상한 없음)
- **최고 성취 기반**(누적 아님): 레벨 **승급 = 큰 점프(팍)**, 같은 레벨 내 성적 갱신 = 소폭.
- **레벨 가중**: 레벨 높을수록 시험 1판의 값이 커짐(= "레벨은 연료"의 구현).
- 못 본 시험은 안 깎고, 더 잘 보면 갱신. → "지금 실력의 최고치".
- 기존 `computePoints`의 0~10000 **정규화 캡은 폐기**. 레벨·성적 기반 개방형 점수로 대체.

### 2.2 활동점수 (누적 · 하루 빈도가 자연 제한)
- 소스 4개(값진 순): **레벨테스트(=실력)**, **오늘의 학습**, **미니게임**, **출석**.
- 활동 소스 상대 크기: **출석 < 오늘의 학습 < 미니게임(성적)**.
- **미니게임**: 원점수 직접 사용 금지(게임별 스케일 상이). **하루 최고 성적을 게임별 정규화** + 판당 소액(참여 표시).
- **자격증 합격·연속출석 스트릭 = 보류**(현재 랭킹 점수 미반영). 자격증은 기존대로 뱃지(`user_titles`)만.
- **가챠·꾸미기 = 절대 미반영**(소비/치장은 성취 아님).

### 2.3 불변식 / 관계
- **활동점수 ≠ 가챠 코인**: 같은 행동이 코인(`user_currency.points`, 소비됨)과 랭킹 활동점수(시즌용, 소비 안 됨)를 **각각 별개 장부**로 적립.
- **정확한 수치는 데이터로 튜닝.** 손으로 확정하는 건 **부등호 "실력 최고치 > 활동 최대치"** 하나뿐(→ 천장은 실력).
- 유저 표시용 점수가 작아 보이면 ×10~×100 뻥튀기 가능(순위 불변, 순수 연출).

## 3. 티어 (5단계 · 백분위)

- **브론즈 / 실버 / 골드 / 플래 / 다이아** (레벨과 분리, 시즌 총점 백분위로 산정).
- 백분위 컷:

| 티어 | 백분위 |
|------|--------|
| 다이아 | 상위 5% |
| 플래 | 상위 5~20% |
| 골드 | 상위 20~45% |
| 실버 | 상위 45~75% |
| 브론즈 | 나머지 25% |

- 기존 엠블렘 7종(iron~master) 중 iron·master는 미사용(상/하위 확장용 보관).

## 4. 스코프 & 윈도우

| 스코프 | 윈도우 | 성격 |
|--------|--------|------|
| 개인 | **시즌** | 현재 경쟁 티어(리셋) = 랭킹 |
| 개인 | **누적** | 평생 업적(역대 최고 티어·뱃지) = 프로필 박제, **순위 없음** |
| 지역/국가/학교 | **데일리** | 오늘 참여 열기 |
| 지역/국가/학교 | **시즌** | 시즌 집단 순위 |

- 개인은 **데일리 제외**(하루 단위 개인 순위는 노이즈).

## 5. 집계 공정성 (베이지안 shrinkage)

- **문제**: 합계 = 인구 많은 지역 고정 1등 / 순수 평균 = 소수 정예(3명) 과대.
- **해법**: 베이지안 보정 평균(IMDb Top250 방식).

```
지역 보정점수 = (n × 지역평균 + K × 전체평균) / (n + K)
```
- `n`=지역 인원, 지역평균=1인당 시즌총점 평균, 전체평균=전체 유저 평균(prior), `K`=스무딩 상수(≈20~30 시작, 튜닝).
- 소수 그룹은 전체 평균 쪽으로 당겨져 못 튀고, 큰 그룹은 K 영향 미미. 평균 기반이라 인구로 자동 1등도 아님.
- **프라이버시 floor(n<5 숨김)는 목적이 달라 그대로 유지**(개인정보 보호). 베이지안은 공정성용.
- 지역/국가/학교 전부 동일 공식. 화면엔 "우리 지역이 함께 쌓은 총점"을 협력 연출로 별도 표시(순위엔 미사용).

## 6. 시즌 라이프사이클

- **주기 = 분기(3개월).** 매일 복귀 동력은 시즌 경계가 아니라 매일 쌓는 활동점수가 담당.
- **리셋 = 활동점수만 0.** 실력점수는 레벨 기반이라 유지 → 티어는 총점 백분위 **자동 재계산**(별도 티어 강등 처리 불필요).
- 시즌 초 실력파 선행 → 진행되며 활동파 추격(매 시즌 활동 재유도).
- **아카이브**: 지난 시즌 최종 티어·순위를 `ranking_season`(가칭) 테이블에 저장 → **개인 누적(업적 박제)**이 여기서 파생.
- ※ 분기 = 90일치 활동 누적 → 실력>활동 부등호 유지되게 스케일 튜닝 필요.

## 7. UI / 표면

### 7.1 Hub HUD — 경험치 바 → 다음 순위 게이지
- 현재 `hud-xp`의 `exp` 바 = `rankPoints/10000`(옛 points), 라벨이 바 안 overlay. **교체.**
- 새 게이지: **"다음 순위까지"**
  - 바 위(밖) 라벨: `다음 순위 · 99위까지 43점`
  - 바 양끝 밖 수치: 왼쪽 내 점수 / 오른쪽 윗사람 점수 (**바 밖**)
  - fill = (내 점수 − 내 순위 하한) / (윗사람 점수 − 내 순위 하한). 가득 차면 추월 = 순위 업.
  - 코인 칩(`gchip`)은 그대로.
- 데이터: `leaderboard`에 "내 순위 + 바로 윗사람 점수" 반환 경로 신설(`myRankContext` 류).

### 7.2 학습 대시보드(`/mypage/learning` = `LearningDashboard.tsx`) 현대화 + 이전

| 현재 요소 | 판정 | 새 처리 |
|-----------|------|---------|
| 등급 히어로(레벨+points+"레벨+맞힌개수=점수") | 교체 | 티어 히어로(현재 티어 + 시즌점수 실력/활동 분해 + 다음 순위 게이지) |
| 점수 추이(computePoints 그래프) | 교체 | 시즌 총점·티어 추이 |
| 통계 "최근 LP변동" | 제거 | 옛 points delta |
| 통계(최고레벨·응시수·평균정답률) | 유지 | + 현재 티어/시즌 순위 |
| 강등 경고(3진아웃) | 유지 | 레벨 강등은 실력 하락 신호 |
| 6축 레이더(레벨별) | 유지 | 실력 심화 렌즈 |
| 활동 잔디 | 유지·확장 | 응시일 → 전 활동일 (7.3) |
| 응시 기록 | 유지 | 그대로 |

**배치(둘로 분리):**
1. **Hub(매일 홈)**: 티어 히어로 + 시즌점수 분해 + 다음 순위 게이지 + **오늘 할 일 체크리스트**(출석·오늘의 문제·오늘의 학습·미니게임 — 각 활동점수 + 완료 ✓). ※ "오늘의 문제"는 신설 슬롯(현재 미존재), "오늘의 학습"=`Daily.tsx` 존재.
2. **실력 심화 뷰(Arena나 Hub 하위 '내 실력')**: 6축 레이더 + 응시 이력 + 활동 잔디 + 최고레벨/정답률.

### 7.3 활동 잔디 — 활동별 색
- **지배색 방식**: 그날 셀 색 = 그날 한 것 중 가장 값진 활동 색.
  - 출석 = 옅은 회색 / 오늘의 학습 = 파랑 / 미니게임 = 주황 / 레벨테스트(응시) = 금색
- **진하기(opacity)** = 그날 총 활동점수. **풀콤(다 한 날)** = 특별색(골드 글로우/그라데이션).
- 호버 툴팁으로 상세("출석·학습·게임 2판"). 셀 분할 방식은 잔디 크기에서 뭉개져 비채택.
- 데이터: 날짜별 활동 종류 플래그(출석/학습/게임/응시) — `daily_activity` + 활동 장부에서 파생.

## 10. 개정 (2026-07-30) — `/ranking` 탭 = 범위별 개인 랭킹

3~9장의 "개인 탭 + 집계(협력) 탭" 구성을 접고, **탭 3개를 전부 개인 랭킹으로 통일**하되 모수만 바꾼다.

| 탭 | 모수 | 라벨 |
|---|---|---|
| 전세계 | 전체 유저 | `rank.tab_world` |
| 내 국가 | `profiles.country_code` = 내 국가 | 실제 국가명(대한민국) |
| 내 지역 | `profiles.region_code` = 내 지역 | 실제 지역명(서울특별시) |

- RPC = **`scoped_top(p_uid, p_limit, p_country, p_region)`** 하나(`migrations/20260730010000_scoped_leaderboard.sql`). 두 코드가 null 이면 `global_top` 과 동일 결과라 전세계 탭이 곧 옛 명예의 전당이다.
- **티어는 전세계 백분위 고정**(사람 단위 속성 — 국가 탭에서 다이아가 됐다 브론즈가 됐다 하면 안 됨), **percentile(상위 N%)만 그 범위 기준**.
- 범위는 **서버가 호출자 프로필에서** 읽는다(클라가 남의 국가/지역 보드를 요청할 수 없음). 비로그인 → `needsAuth`, 온보딩 전 → `needsRegion` 로 빈 보드 + 안내.
- 집계(베이지안 버킷) RPC `region_/country_/school_leaderboard` 는 **살아있다** — 소비처가 `/arena` 지도 하나로 줄었을 뿐(8장 "월드아레나 = 집계의 지도 뷰"가 실제로는 유일 뷰가 됨). 랭킹 탭의 오늘/시즌 토글·평균/참여율 카드는 제거.

## 10. 열린 항목 (구현 단계 결정/튜닝)

- 실력/활동 점수 **정확 수치 튜닝**(부등호만 사수).
- 자격증 합격·연속출석 스트릭 반영 여부(현재 보류).
- 시즌 아카이브 스키마 상세, 시즌 경계(캘린더 분기 vs 고정 12주).
- 학습 대시보드 분리 최종 확인(Hub=시즌/오늘 vs 한 페이지).
