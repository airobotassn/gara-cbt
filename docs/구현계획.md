## 0. 확정된 결정 (구현 기준)

- **국가**: IP 자동판정, 시/도와 함께 첫 로그인에서 확정 → **락**.
- **지역**: **ISO 3166-2**(`KR-11`=서울…). IP 시/도 best-guess **프리필 + 유저 수정 가능** → 확정 시 **락**.
- **락**: 확정 후 **유저 UI 수정 불가**, **어드민/DB만 변경**(오배정 CS용).
- **비공개/전국 없음**: 모두 실제 시/도 배정. **스킵 없음**(프리필값 확인/수정만).
- **학교**: 선택·**수정 가능**, **정규화 리스트**(자동완성) — 학교 대항 순위 대비.

### 2-3. schools (정규화)
```sql
create table if not exists schools (
  id       text primary key,     -- 공공데이터 학교ID or 자체 slug
  name     text not null,
  kind     text,                 -- university|college|... (초기엔 대학 위주)
  region_code text,              -- 선택: 학교 소재 시도
  active   boolean not null default true
);
create index if not exists schools_name_trgm on schools using gin (name gin_trgm_ops); -- 자동완성(pg_trgm)
alter table schools enable row level security;
create policy "schools_select_all" on schools for select using (true);  -- 목록은 공개 read
```
- **데이터 소스**: 공공데이터포털 "대학 목록"/학교알리미 등에서 대학(4년제+전문대) 시드. 초기 범위=대학. (고교 포함은 추후.)
- 자동완성: `pg_trgm` 유사도 or `ilike` prefix. 함수(`school-search`) or 공개 select 둘 다 가능 — 목록이 공개 read라 **클라 직접 select도 허용**.

### 2-4. 락 강제 트리거 (서버 방어)
```sql
create or replace function enforce_region_lock() returns trigger language plpgsql as $$
begin
  if OLD.region_locked_at is not null
     and (NEW.country_code is distinct from OLD.country_code
          or NEW.region_code is distinct from OLD.region_code) then
    -- 어드민 우회: 세션 GUC 로만. 일반 경로(본인 update)에선 항상 차단.
    if coalesce(current_setting('app.allow_region_change', true), 'off') <> 'on' then
      raise exception 'region is locked';
    end if;
  end if;
  return NEW;
end $$;
drop trigger if exists trg_region_lock on profiles;
create trigger trg_region_lock before update on profiles
  for each row execute function enforce_region_lock();
```
> 클라가 RLS로 profiles를 update해도 country/region은 이 트리거가 막는다. 학교/닉네임/아바타 update는 영향 없음.

## 3. IP 지오 획득 방식 (설계 선택)

문제: 프론트=CF 정적자산이라 `request.cf` 없음. Supabase 엣지함수도 CF 지오를 못 봄(자체 인프라). → 국가/시도 자동판정 소스를 하나 정해야 함.

| 옵션 | 방식 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| **A. CF Worker `/api/geo`** | `wrangler.jsonc`에 `main` Worker 추가, 특정 라우트만 `request.cf` 반환하고 나머지는 assets로 폴백 | 무료·정확·서버측 | 배포 구조 살짝 복잡(assets+worker) | **권장** |
| B. 외부 지오 API | 온보딩 시 브라우저가 ipapi/ipwho.is 호출 | 인프라 변경 0 | 외부 의존·레이트리밋·차단 가능 | 대안 |
| C. Supabase 함수에서 IP 지오코딩 | `x-forwarded-for` + 외부 API/MaxMind | 함수에서 완결 | City DB 무거움·외부 의존 | 비권장 |

**중요**: 어떤 옵션이든 **IP값은 "프리필"용**일 뿐, 최종 지역은 유저의 **선택(선언)**이라 IP 위조 위험이 크지 않다. 진짜 지켜야 할 건 **락**(§2-4, §4)뿐. 그래서 A로 국가+시도 추정만 채워주고, 확정은 유저가.
- CF `cf.country`(alpha-2)는 바로 씀. `cf.region`/`regionCode`는 **ISO 3166-2로 매핑 테이블** 필요(예: region 이름/코드 → `KR-11`). 매핑 실패 시 시도는 빈값(유저가 직접 선택).

## 4. 온보딩 플로우 (첫 로그인 → 확정 → 락)

```
구글 로그인 → /auth/callback
   └─ 프로필 조회: region_locked_at == null 이고 정식회원(구글) ?
        ├─ 예 → /onboarding 로 이동 (게이트)
        └─ 아니오 → 원래 목적지로
```

### `/onboarding` 화면 (신규 페이지)
```
┌──────────────────────────────────────────┐
│  어느 지역에서 함께 하시겠어요?               │
│                                            │
│  국가   [ 🇰🇷 대한민국            ▼ ]  (IP 자동) │
│  지역   [ 서울특별시              ▼ ]  (IP 추정, 수정 가능) │
│                                            │
│  학교(선택) [ 학교 검색…          🔎 ]  (자동완성)│
│                                            │
│  ⚠️ 지역은 한 번 정하면 바꿀 수 없어요.        │
│              [ 이대로 시작 ]                 │
└──────────────────────────────────────────┘
```
- 프리필: `/api/geo`(옵션 A) 결과로 국가/시도 채움. 실패해도 국가 드롭다운은 전체 목록에서 선택 가능.
- "이대로 시작" → `set-region` 엣지함수 호출 → 성공 시 원래 목적지로. 학교는 같이 보내거나 이후 마이페이지에서.
- 뒤로가기/닫기로 빠져나가도 게이트는 다음 진입 때 다시 뜸(락 전까지 반복). **자동배정 아님** — 유저가 버튼을 눌러야 확정.

### `set-region` 엣지함수 (신규, service role)
```
입력: { country_code, region_code, school_id? }
1. getUser → 익명/미로그인 거부
2. region_code ∈ 허용목록(regions 상수) 검증, country_code 형식 검증
3. UPDATE profiles SET country_code, region_code, region_locked_at=now()
     WHERE id=uid AND region_locked_at IS NULL   ← 경합 방지 가드
   영향행 0 → 이미 확정됨(409)
4. school_id 있으면 함께 set (락 아님)
```
> `_shared` import하므로 **CLI로만 배포**(대시보드 금지) — CLAUDE.md 규칙.

### 마이페이지
- **학교**: 자동완성 셀렉터 + 저장(클라 직접 update 또는 `set-school`). 언제든 변경.
- 국가/지역: **읽기 전용 표시**(회색), "변경 불가/문의" 안내.

## 5. 리더보드 (지역·국가·학교 집계)

기존 `global_top`(개인) 유지 + 신규 집계 RPC. 순위점수 = **지역 평균 레벨 × 오늘 참여율**.

### 신규 RPC (설계)
```sql
-- 지역(시도) 순위: 국가 내 region_code 별
create or replace function region_leaderboard(p_country text default 'KR')
returns jsonb language sql stable as $$
  -- 각 region_code 에 대해:
  --   avg_level        = avg(user_progress.rank)                (해당 지역 유저)
  --   participation    = (오늘 활동 유저 수) / (지역 총 유저 수)
  --   score            = avg_level * participation
  -- deactivated 제외, region_code not null
  ...
$$;
-- 국가 순위: country_code 롤업 (세계 8위 프레이밍)
-- 학교 순위: school_id 그룹 (동일 공식, 학교 대항)
```
- **데일리 순위**(오늘 참여율 반영, 매일 변동) + **시즌 순위**(누적) 병행 → 참여율 집계 창(오늘/시즌) 파라미터화.

### ⚠️ 의존성 — "오늘 참여율"의 소스
- 참여율 = 오늘 활동한 유저 비율. **활동 신호**가 필요한데 Daily Study가 아직 없음.
- **임시**: `test_attempts.created_at`(오늘) distinct user 로 프록시.
- **정식**: 하루 완료 이벤트(`complete-daily` → `daily_activity(user_id, day)`)로 교체 — 오늘의 콘텐츠 열람+10초 = 참여 1건. **Phase 2에서 정의됨**.
- 리셋: 데일리=날짜 경계(KST), 시즌=시즌 정의 필요(별도 결정).

### 프론트
- `/ranking` 페이지에 탭 추가: **개인 / 지역 / 국가 / 학교**. 지역 카드에 "서울 3위 · 평균 62 · 오늘 참여율 41%" 식.
- 협력 프레이밍 카피("우리가 올라간다", 하락 서사 금지)는 i18n 6개국어.

## 9. Phase 2 — 캐릭터 & 성장 엔진 (일부 확정)

### 확정
- **캐릭터 생성물 = 아바타**: 새 캐릭터 시스템에서 생성/꾸민 캐릭터를 `profiles.avatar_url`에 저장해 프로필 아바타처럼 사용·변경. avatar_url 스킴에 캐릭터 타입(`char:…`) 추가, 기존 `gem:`/`img:`와 공존.
  - 반영 지점: `src/lib/avatar.ts`(parseAvatar) · `GemAvatar`(렌더러에 캐릭터 케이스) · `leaderboard`의 `mapUser`(현재 `gem:`/`img:`만 처리).
- **레벨 = 진화**: Level Test 레벨 → 캐릭터 진화 단계 연출. 진화=실력 획득(변경 불가), 꾸미기=변경 가능 — 분리.
- **쇠퇴 = 위안형**: 자다가 복귀하면 반김(벌 없음).
- **보상 경제 = 꾸미기 파츠 · 하이브리드(뽑기+상점)**: 매일 학습 → 포인트 → 파츠. 뽑기(꽝없음·중복환급·천장 pity) + 상점(포인트로 원하는 파츠 확정 구매) 병행. 마일스톤 = **누적 스탬프**(연속 스트릭 ❌) → 뽑기권/특별 파츠.
  - **외형 전용**(실력·진화 영향 ❌ → pay/grind-to-win·시험 신뢰도 오염 방지).
  - 신규 데이터(예): `user_currency`(포인트 잔액) · `user_cosmetics`(파츠 인벤토리) · `gacha_log`(천장 카운터) · 스탬프 진행.
- **하루 완료 = 오늘의 콘텐츠 소비**: 앱/웹 로그인 → 오늘의 콘텐츠 열람. **정답/풀이 무관**(콘텐츠가 문제형+수동 소비형 혼재라 완료=소비 기준). 완료 신호는 타입별(수동=끝까지 봄, 문제형=열람/시도). = 매일 보상·성장 트리거 = **지역 참여율 신호**(§5).
  - 구현: 체류는 클라 추적(visibilitychange/focus — 기존 `useAntiCheat` 이탈감지 재사용) → `complete-daily` 엣지함수 리포트 + **하루 1회 서버 가드**(이미 오늘 완료면 무시). 보상=외형 전용이라 고강도 안티치트 불필요.
  - 플랫폼: 웹 우선(현 스택), 앱은 이후(PWA/네이티브).
- **초기 캐릭터 = 기본 1종**: 랜덤/커스터마이즈 없이 시작. 꾸미기는 파츠 해금으로.
