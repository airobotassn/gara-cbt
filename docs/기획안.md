# AI 활용능력 레벨테스트 사이트 — 기획안 (v2)

> 최종 업데이트: 2026-06-11. 구현 중 합의된 결정들을 모두 반영한 버전.

## Context (왜 만드는가)
"당신의 AI 활용능력은 어느 정도인가요?"를 묻는 미니멀 랜딩에서 시작해, 누구나(비로그인 포함) 20문항 레벨테스트를 보고 **점수 → (로그인 시) 티어·영역분석·오답노트**를 받는 사이트. 핵심 의도:
- **비로그인도 응시 가능**하되 **총점(점수)만** 노출. 티어·레이더·해설·오답노트는 **로그인 후 잠금 해제**로 전환 유도
- 비로그인 응시 후 결과창에서 **로그인하면 그 결과 그대로 유지**되어 잠금 해제
- 티어는 "그날의 스냅샷"이 아니라 **유저에게 귀속된 누적 6축 레이팅(롤 MMR식)** — 잘 보면 오르고 못 보면 내림. 비로그인은 누적 없음
- 모수가 없으므로 % 대신 **롤 스타일 고정 구간 티어**(초기엔 가짜 분포) + **티어 평균 레이더 오버레이(your.gg식)**
- 부정행위는 "완벽 차단"이 아니라 **쉬운 컨닝 봉쇄 + 서버 단일지점 잠금**이 목표

## 핵심 설계

### 1) 인증 & 비로그인 데이터 유지 — claim 토큰 이관 방식
`linkIdentity`는 "이미 가입된 구글 계정"과 충돌(identity already linked)이 발생하므로 **사용하지 않는다.** 대신 **일반 구글 로그인 + attempt 이관(claim 토큰)** 으로 통일 → 신규/기존 계정이 한 경로로 처리되어 충돌 분기가 없다.

- 시험 시작 시 세션 없으면 `signInAnonymously()` (비로그인도 익명 세션으로 응시)
- 제출 시 서버가 그 attempt에 **무작위 일회성 `claim_token`** 발급 → **익명 소유자에게만** 반환
- 결과창 "로그인하고 분석 보기" → `{attemptId, claimToken}`을 localStorage에 저장 후 일반 `signInWithOAuth(google)`
- 리다이렉트 복귀 후 `get-result(attemptId, claimToken)` 호출 → 서버가 토큰 검증 후 **attempt를 현재 로그인 user로 이관**하고 전체 결과 반환
- 토큰 불일치/이미 이관됨 → 이관 거부(도용 방지)

### 2) 서버 단일지점 잠금 (가장 중요 — 화면 잠금만으로는 부족)
익명 인증도 진짜 `auth.users` + JWT를 가진 로그인 상태다. RLS가 "본인 row read 허용"이면 익명 유저가 클라이언트로 잠금 데이터를 직접 쿼리해 레이더/오답/티어를 재구성할 수 있다. → **화면에서 가리는 것으로는 불충분.**

**해결: 잠금 데이터 자체를 클라가 못 받게 한다.**
- **RLS**: `test_attempts` / `attempt_answers` → **클라이언트 직접 SELECT 전면 금지**(service role 전용, `questions.correct_index`와 동일 취급)
- **모든 결과 read는 Edge Function으로만**:
  - `get-result(attemptId, claimToken?)`: ① 주인 확인(또는 토큰으로 이관) ② JWT `is_anonymous` 확인 ③ **익명 → `total_correct`만** ④ **영구유저 → 티어·레이더6축·오답·해설 전부**
  - `list-attempts()`: 로그인 유저의 제출 기록 목록(대시보드/랭킹 본인 티어용)
- 컬럼 단위 분기(총점은 보이고 티어는 숨김)는 RLS 행 단위로 불가능 → 함수에서 한 줄로 해결
- **자동 잠금해제**: 로그인 후 `get-result` 재호출 → 같은 함수가 전체 반환 → 잠금 해제. 추가 마이그레이션 불필요

### 3) 채점 · 누적 티어 · 레이더 (서버 전용, 롤 MMR식)
정답·해설은 클라로 절대 안 내려감(`start-test`는 문제 텍스트만). 채점·레이팅 갱신은 서버에서만.

**티어 = 유저에게 귀속된 누적 6축 레이팅(MMR).** 테스트는 그 레이팅을 갱신하는 이벤트일 뿐 — 잘 보면 오르고 못 보면 내린다. 비로그인(익명)은 누적 레이팅 없음(로그인 유도책). 익명 attempt는 perf만 기록해뒀다가 **이관(claim) 시점에 그 계정 레이팅에 반영**.

- **유저마다 6축 누적 레이팅** `R[축] (0~100)` 보유 (`user_skill`)
- **이번 테스트의 축별 성적**: `perf = LEVEL_WEIGHT[level] × (보정정답률)^1.5`  (0~100)
  - **추측 보정**: `보정정답률 = max(0, (정답률 − 0.25) / 0.75)` — 4지선다 무작위 기댓값 25%를 깎아내, **순수 찍기는 레벨 무관 0점**(레벨 높여 찍기로 floor 먹는 우회 차단). `GUESS_BASELINE=0.25`
  - `LEVEL_WEIGHT = {1:15, 2:28, 3:42, 4:58, 5:72, 6:86, 7:100}` — **레벨이 천장**. 낮은 레벨로는 상위 티어 도달 불가(레벨 게이밍 차단)
  - `^1.5` = **실수 페널티**(절반 틀리면 훅 떨어짐)
- **갱신(EWMA, 비대칭)**: `R_new = R + K × (perf − R)` — 상승 `K=0.25`(빠르게) / **하락 `K=0.1`(천천히)**. 한 판 망쳐도 살짝만 내려가고 꾸준히 못 해야 강등. **볼륨 파밍 불가**(실력 천장으로 수렴)
- **배치(placements)**: 첫 응시는 `K = 1`로 perf를 그대로 박아 초기 배치
- **종합 티어**: `overall = 0.7 × mean(6축) + 0.3 × min(6축)` → **약점 패널티**(한 축 빵꾸나면 묶임 → 골고루 잘해야 승급). 밴드(0~100):
  - IRON 0 / BRONZE 12 / SILVER 26 / GOLD 42 / PLATINUM 60 / DIAMOND 80 / MASTER 94
- **결과창 = 롤 LP 느낌**: 축별 변동(▲+6 / ▼-3) + 종합 티어 승강 표시
- 모든 계수(`K`, 지수, `0.7/0.3`, `LEVEL_WEIGHT`, 밴드)는 한 곳(`scoring.ts`)에서 config
- **⚠️ 멱등성(중복 반영 금지)**: 레이팅 갱신은 **attempt당 정확히 1회**만 일어나야 한다. `get-result`는 결과창 진입·새로고침마다 호출되므로, 장치가 없으면 F5만으로 레이팅이 계속 올라감(버그+부정행위 통로). → `test_attempts.applied` 플래그로 가드: `applied=false`일 때만 `user_skill`에 반영하고 즉시 `applied=true`, 이후 호출은 조회만. (반영+플래그 set은 한 트랜잭션으로 원자적 처리)
- **결과 스냅샷(과거 코히런스)**: 반영 직후 attempt에 `rating_after`(6축)·`overall_after`·`tier_after`를 저장. 과거 시험을 열면 **그 시점 티어/레이더**가 보임 — 현재 마스터라도 과거 실버 결과는 실버로 표시(스냅샷 없으면 현재 `user_skill`로 폴백)

**레이더 차트 (your.gg식)**
- 반경은 **0~100 고정 + 제곱(sqrt) 스케일** → 채움 정도가 곧 티어(꽉 차면 마스터)이되 **저티어도 또렷**(아이언≈반지름 1/3). op.gg식 가독성
- **2겹 오버레이**: 내 6축(솔리드 컬러) + **이 티어 평균(점선 고스트)** → 피어 대비 강·약점 한눈에. (옵션: 윗티어 평균 깔아 "승급 가이드")
- 티어 평균은 모수 없으니 **티어별 시드 프로필**(`tier_avg_profile`)로 시작 → 유저 쌓이면 `AVG(R) GROUP BY tier`로 실데이터 교체(화면 코드 불변)

### 4) 쿨다운 & attempt 수명 (farming/방치 대응)
- **쿨다운·랭킹은 오직 `status='submitted'` 기준** → 방치된 in_progress는 쿨다운 미작동
- **3일 쿨다운을 두 지점에서 강제**:
  - 로그인 `start-test`: 최근 3일 내 submitted 있으면 시작 거부
  - **이관(claim) 시점**: 대상 계정이 최근 3일 내 submitted 있으면 **이관 거부** → "익명 풀기→내 계정 이관" 반복 farming 차단 (점수만 보이고 상세 잠금 유지)
  - ※ 다중 구글 계정 farming은 신원확인 없이는 불가(범위 밖)
- **status enum**: `in_progress` | `submitted` | `expired`
- **in_progress TTL = 2시간**(`ATTEMPT_TTL_MINUTES=120`, 화면 타이머 아님, 서버 안전장치):
  - `start-test`: 같은 유저의 기존 in_progress는 모두 `expired` 처리(동시 1개) + TTL 초과분 `expired`
  - `submit-test`: 대상이 in_progress 아니거나 `started_at` TTL 초과면 거부+`expired`
- **새로고침/창 닫음 = 무효(다시 시작)**: 문제는 메모리(router state)로만 보유 → 새로고침 시 데이터 소실 → 재시작 안내. 버려진 attempt는 TTL로 정리

### 5) 부정행위 방지 (현실적 목표)
- **1층(항상)**: 시험 페이지 우클릭·텍스트선택·드래그·복사 차단
- **2층(적용)**: 시작 시 전체화면 진입 + 탭/창 이탈 감지 → 경고 + `violation_count` 기록, **3회 누적 시 자동 제출**(`MAX_VIOLATIONS`)
- **3층**: 정답·채점·결과 서버 전용 + 문제 랜덤 출제 + (위 2번) 서버 단일지점 잠금
- ⚠️ **명시적 한계**: 화면 캡처 자체는 웹에서 차단 불가, 폰 카메라/듀얼모니터는 못 막음. **제한시간을 제거**했으므로 "캡처→AI 질의" 방어는 약함 — 이 부분은 트레이드오프로 수용함

## DB 스키마 (요약)
```
profiles(id PK→auth.users, display_name, avatar_url, is_anonymous, created_at)
questions(id PK, level 1..7, category enum(6축), prompt, options jsonb,
          correct_index int, explanation text, active bool)   -- 정답/해설은 service role 전용
test_attempts(id PK, user_id→auth.users, level, status(in_progress|submitted|expired),
              started_at, submitted_at, total_correct, total_questions,
              axis_perf jsonb, deltas jsonb,                     -- 이 시험의 축별 perf/변동
              rating_after jsonb, overall_after numeric, tier_after text,  -- 반영 직후 스냅샷(과거 결과 코히런스)
              violation_count, claim_token, applied bool)        -- applied=레이팅 반영 여부, 클라 직접 read 금지
attempt_answers(id PK, attempt_id→test_attempts, question_id→questions,
                selected_index, is_correct, category, time_spent)  -- 클라 직접 read 금지
user_skill(user_id PK→auth.users,                              -- 유저 누적 6축 레이팅(영구유저만)
           r_prompt, r_model, r_verify, r_automation, r_data, r_ethics numeric(5,2),  -- 0~100
           overall numeric, tier text, attempts_count int, placed bool, updated_at)
tier_avg_profile(tier PK, r_prompt, r_model, r_verify, r_automation, r_data, r_ethics numeric)  -- 시드(가짜)→실데이터
```
**RLS 원칙**: `questions`/`test_attempts`/`attempt_answers`/`user_skill`은 클라 직접 SELECT 불가(service role 전용). 결과는 Edge Function으로만 서빙. `tier_avg_profile`은 집계값이라 공개 read 가능.

## Edge Functions
- `start-test(level)` — 쿨다운·이전 in_progress expire → 랜덤 20문항(정답 제외) → attempt 생성
- `submit-test(attemptId, answers)` — TTL/상태 검증 → 채점 → 축별 perf 기록 → **로그인 유저면 `user_skill` 레이팅 갱신**(placements/EWMA)·`applied=true`, **익명이면 갱신 없이 claim_token 포함**(총점만)
- `get-result(attemptId, claimToken?)` — 주인확인/이관(+쿨다운) → **이관 시 미반영 attempt의 perf를 그 계정 `user_skill`에 적용** → `is_anonymous` 분기로 반환(영구유저=티어·6축 누적레이팅·변동·`tier_avg_profile`·오답·해설)
- `list-attempts()` — 로그인 유저 제출 기록 목록(+레이팅 변동 히스토리)

## 검증 (end-to-end)
- 비로그인 응시 → 결과창 **총점만** 노출, 티어/레이더/해설 잠김 → 구글 로그인 → **같은 결과로 잠금 해제 + 유지** 확인
- **서버 잠금**: 익명 세션으로 `test_attempts`/`attempt_answers` 직접 쿼리 시 **0행/거부** 확인(개발자도구)
- **쿨다운**: 3일 내 재응시 거부 + **익명 farming 이관 거부** 확인
- **방치**: in_progress 2시간 후 expired, 새로고침 시 재시작 확인
- **부정행위**: 탭 전환 경고·카운트, 3회 자동제출, 복사/우클릭 차단 확인
- 응답에 `correct_index` 미포함 확인
- **누적 레이팅**: 잘 본 테스트 후 축별 ▲상승·종합 티어 갱신, 못 본 테스트 후 ▼하락 확인 / 첫 응시 배치 동작 / 같은 레벨 반복으로 실력 천장 이상 안 오름(파밍 불가) 확인
- **익명→이관**: 익명 응시는 누적 미반영(총점만) → 로그인 이관 시 그 attempt가 `user_skill`에 1회 적용·`applied` 중복반영 없음 확인
- **레이더**: 0~100 고정 도메인(마스터=꽉 참/아이언=작음), 티어 평균 고스트 오버레이 표시 확인

## 추가로 정할 것
- 문제은행 실제 문항(현재 샘플 시드) / 가짜 분포 규모

- **`tier_avg_profile` 시드값**: 티어별 6축 평균 프로필(your.gg 오버레이용 가짜 데이터)
