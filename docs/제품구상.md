## 0. 한눈에

**개인 캐릭터**를 허브로 3개 제품을 엮는다.

```
                    ┌─────────────┐
        ┌──────────▶│  자격증      │◀── (레벨 도달·완강 시 응시비 할인)
        │           │ CARIS 자격검정│
        │           └─────────────┘
        │                  ▲
 ┌──────┴──┐        ┌──────┴──────┐        ┌──────────────┐
 │  User   │───────▶│  Lecture    │───────▶│ 강의 파트너   │= 개인 캐릭터
 │ (타깃)   │        │  (강의)      │  강의Agent └─────┬────────┘
 └──────┬──┘        └─────────────┘                 │
        │                                            ▼
        │           ┌─────────────────────────────────────┐
        └──────────▶│  CARIS ARENA (무료)                   │
                    │  Daily Study ─(성장)─▶ 개인 캐릭터       │
                    │  Level Test  ─(진화)─▶ 개인 캐릭터·자격증 │
                    │  국가/지역 경쟁 (별도)                    │
                    └─────────────────────────────────────┘
```

**개인 캐릭터가 세 제품을 관통하는 축**: ARENA에서 키우고 → Lecture에서 강의 파트너가 되고 → 성장/완강이 자격증 할인으로 연결.

## 1. User (타깃)

취업·이직을 준비하며 **AI·Robot 역량**이 필요한 사람.
- 대학 고학년
- 취준생
- 재취업·업종변경 준비자
- 미래를 대비하고 싶은 직장인

진입 경로: **자격증 · CARIS ARENA · Lecture** 세 갈래.

---

## 2. CARIS ARENA (무료 · 성장 엔진)

### 메인 엔진 = 캐릭터 성장 + 매일 학습
- 캐릭터를 **키우고 꾸미는 재미**를 중심에 둔다.
- 남과 겨루는 경쟁이 아니라 **"어제보다 나아진 나"**를 보여주는 방식.
- 도태 불안으로 들어온 타깃을 **자극해 내쫓지 않고 오히려 위안**을 준다.

### 캐릭터 성장
- 매일 제공되는 문제 · 출석 체크로 캐릭터를 성장시킴.
- 며칠 안 오면 캐릭터가 **쇠퇴(녹·고장)** → 다시 문제 풀면 복구.
  - 대안 톤: 캐릭터가 **자는 상태로 기다리다 복귀하면 반김**.
- **오늘의 문제 / 대박 문제 / 한정 문제** 등 한정 이벤트를 부여.
- 성장의 외형화: **뱃지 + 캐릭터 외형 변화**.

### Daily Study & Level Test (각각 독립 — 게이팅 없음)
> **변경(2026-07-13)**: 예전엔 "Daily Study를 채우면 레벨테스트가 열림"(게이팅)이었으나 → **Daily Study와 Level Test가 각각 독립**으로 바뀜. Daily Study가 레벨테스트를 여는 관계 삭제.
- **Daily Study** = 매일 학습 → 캐릭터 **성장**.
- **Level Test** = 별도로 존재. 실력 측정 → 캐릭터 **진화**(레벨업) + **자격증 할인** 연결.
- 둘 다 CARIS ARENA 하위에 나란히: `CARIS ARENA → Daily Study(성장)`, `CARIS ARENA → Level Test(진화)`.

### 국가/지역 경쟁 (협력형)
- 국가·지역 집단에 **익명 합산**해 겨룸 — 예: "대한민국 평균 62점·세계 8위", "서울 3위". **개인 순위 노출 X**.
- 프레이밍 = **"우리가 올라간다"** (꼴찌·하락 서사 금지).
- **순위 점수 = 지역 평균 레벨 × 오늘 참여율**.
- **데일리 순위**(매일 리셋·크게 변동 → 오늘 올 이유) + **시즌 순위**(누적·천천히 → 자부심) 병행.

## 3. Lecture (강의)

- **강의 파트너 = 개인 캐릭터**: 내가 꾸미고 성장시킨 캐릭터가 내 강의 파트너가 됨.
- AI 기반 **대화형 학습 도우미**.
- 사용자 데이터 기반 학습(어떤 강의) **추천**.
- **유료 API 필요**: 1강의(30분)당 **~300원**(질문 100개 내외).
- **강의 Agent → 자격증** 연결.

---

## 4. 자격증 (CARIS 자격검정)

수익화 훅(할인 유도):
- **레벨테스트 특정 레벨 도달 시** → 자격증 응시비용 할인.
- **강의 완강 시** → 자격증 응시비용 할인.

---

## 5. 연결 관계 (캔버스 화살표 전사)

- User → 자격증 / Lecture / CARIS ARENA
- CARIS ARENA → 개인 캐릭터 / Daily Study / Level Test  (셋 다 직접 분기)
- Daily Study ─(성장)▶ 개인 캐릭터
- Level Test ─(진화)▶ 개인 캐릭터
- Level Test → 자격증
- 자격증 → 개인 캐릭터
- Lecture → 강의 파트너(= 개인 캐릭터)
- 강의 Agent → 자격증

## 6. 설계 결정 (구현 스펙)

> 캔버스엔 없고, 대화로 잠근 내용. 여기가 구현 기준.
> **[확정]** = 사용자가 직접 결정 · **[제안]** = Claude 제안(기술/UX 수단, 변경 가능). 확정일 2026-07-13.

### 6-1. 지역/국가 온보딩 (국가·지역 경쟁의 기반)

- **[확정] 국가**: IP 자동판정. (`cf.country` 등 *취득 수단*은 [제안] → `구현계획.md` §3)
- **[확정] 지역**: **ISO 3166-2**(`KR-11`=서울…). 시/도는 **유저가 선택**.
- **[확정] 프리필**: 온보딩 화면에 IP 추측값을 **미리 채워두고** 유저는 **확인/수정만**. 빈 칸으로 두지 않음. 정확도 낮은 시/도도 그 자리에서 바꿀 수 있어 자동배정 후 즉시 락 ❌.
- **[확정] 락**: 첫 로그인에서 확정하면 **유저 UI 수정 불가**.
  - **[확정] 어드민/DB에선 변경 가능**(오배정 CS 대응 escape hatch).
  - [제안] 확정 버튼 옆 "한 번 정하면 못 바꿔요" 문구.
- **[확정] 비공개/전국 옵션 없음**: 모두 실제 시/도 배정. 개인 순위는 비노출(집계만)이라 프라이버시 노출이 없고, "미지정" 죽은 버킷 회피.
- **[확정] 스킵 없음**: 프리필값 확인/수정만, 건너뛰기 버튼 없음.

### 6-2. 학교

- **[확정] 선택 항목**, **수정 가능**(락 없음).
- **[확정] 정규화 리스트**(자유 텍스트 ❌) — 학교 대항 순위 대비. 자유 텍스트는 "서울대"/"서울대학교"/"SNU"가 갈려서 집계 불가.
- [제안] 입력 UX = 학교 테이블 기반 **자동완성**.

### 6-3. 스키마 스케치 (제안 — 미확정)

```sql
-- profiles 확장
alter table profiles add column if not exists country_code text;      -- ISO "KR", 최초 확정 후 락
alter table profiles add column if not exists region_code  text;      -- ISO 3166-2 "KR-11", 최초 확정 후 락
alter table profiles add column if not exists school_id    text;      -- schools FK, 선택·수정가능
alter table profiles add column if not exists region_locked_at timestamptz;  -- 확정 시각(락 판정)

-- 학교 정규화 테이블 (자동완성·학교순위 대비)
create table if not exists schools (
  id text primary key,        -- 자체 코드 or 공공데이터 학교ID
  name text not null,
  kind text,                  -- 대학/전문대 등
  ...
);
```
- 리더보드 집계: `group by region_code` → 국가는 `country_code` 롤업, 학교는 `school_id`.
- **미정**: 지역 평균/참여율 저장 위치(집계 테이블 vs RPC 온더플라이), 데일리/시즌 리셋 방식, 학교 리스트 데이터 소스(대학 범위·공공데이터 시드).

### 6-4. 캐릭터 & 성장 엔진 (메인 엔진)

- **[확정] 캐릭터 생성물 = 아바타**: 새 캐릭터 시스템에서 **생성/꾸민 캐릭터**를 기존 `profiles.avatar_url` 슬롯에 넣어 **프로필 아바타처럼 사용·변경**. → avatar_url 스킴에 캐릭터 타입(예: `char:<config>`) 추가, 기존 `gem:`/`img:`와 공존.
- **[확정] 레벨 = 진화**: Level Test로 오른 레벨 = 캐릭터 **진화 단계**(연출). 진화는 **실력으로 획득**(임의 변경 ❌) — 꾸미기(변경 가능)와 분리.
- **[확정] 캐릭터 변화 3축**: ①진화=레벨(**모양 변신**) ②꾸미기=파츠(취향) ③**자격증=칭호**(성취, §6-5). 자격증은 진화가 모양을 담당하니 **모양 변신이 아니라 칭호**로 표현(축 안 겹침).
- **[확정] 쇠퇴 = 위안형**: 며칠 안 오면 벌(녹/고장)이 아니라 **자다가 복귀하면 반김**.
- **[확정] 보상 = 꾸미기 파츠 · 하이브리드(뽑기+상점)**: 매일 학습 → 포인트 → 꾸미기 파츠(뽑기+상점 병행). 이걸로 '캐릭터 꾸미기 방식'도 해결(파츠 해금 = 데일리 보상).
- **[제안] 보상은 외형 전용**: 파츠/뽑기는 꾸미기만, 실력·진화 영향 ❌ (진화=Level Test만 → pay/grind-to-win·시험 신뢰도 오염 방지). *ㅇㅇ로 동의 간주 — 아니면 정정.*
- **[제안] 2층 + 위안 가드**: ①매일 = 컨디션 유지 + 포인트 ②마일스톤 = 뽑기권/특별 파츠. 뽑기는 꽝없음·중복환급·천장(pity); 마일스톤은 연속 스트릭 ❌ → **누적 스탬프**(하루 놓쳐도 안 무너짐).
- **[확정] '하루 완료' = 오늘의 콘텐츠 소비**: 앱/웹 로그인 → 오늘의 콘텐츠를 열람. 오늘의 콘텐츠는 **문제형 + 수동 소비형(문제 없이 읽/보는 것) 혼재** → 완료는 '문제 풀이'가 아니라 **소비 기준**, **정답/풀이 무관**(위안 톤 · 도태불안 타깃 압박 X). = 매일 보상·성장 트리거 = 지역 참여율 신호.
  - [제안] 완료 신호는 콘텐츠 타입별: 수동 소비형=**끝까지 봄**(영상 X%/글 스크롤 끝), 문제형=열람/시도. (순수 10초 타이머보다 어뷰징에 강함)
- **[확정] 초기 캐릭터 = 기본 1종만**: 첫 생성은 랜덤/커스터마이즈 없이 기본 캐릭터. 꾸미기는 이후 파츠 해금으로.
- **[확정] 스페셜 데이 (매일과 별개)**: 옛 '대박/한정 문제'를 하나로 통합(두 네이밍 폐기). **격주 1회** 열리고 보상 = **뽑기권 1장**. → 구조 2단계: 매일=포인트(오늘의 콘텐츠), 격주 스페셜 데이=뽑기권 1장.
- **[범위 밖] Daily Study 문항**: 사용자가 별도 제작 — 설계 대상 아님.

### 6-5. Level Test 진화 & 자격증 할인 (Phase 3)

- **[확정] 진화 연출 = 일단 대충(MVP)**: Level Test 레벨↑ → 캐릭터 진화. 초기엔 **기존 레벨→엠블렘/에셋(`TierEmblem`) 재사용** 수준으로 간단히, 화려한 애니는 나중.
- **[확정] 레벨업 → 자격증 쿠폰**: 레벨 **최초 도달 시마다 1장** 발급(강등 후 재승급 재발급 ❌ = 파밍 방지, 7단계라 최대 ~6장).
  - **[확정] 중복 적용 불가**: 1회 결제에 쿠폰 1장만(스택 ❌).
  - 의존성: 쿠폰 사용처(자격증 결제)가 아직 데모 → 결제 실장 시 발급/차감 연동.
- **[확정] 자격증 획득 → 캐릭터 칭호(성취 마커)**: 자격증 따면 **칭호/엠블럼** 부여(모양 변신 ❌ — 진화와 축 분리). **구매·뽑기 불가**(진짜 취득자만) · **리더보드·프로필 노출**(전환 유도) · 급수(Pro 4~1급·Master)는 **칭호 텍스트/엠블럼으로 자연 구분**(추가 비용 거의 0). 톤 = '따면 해금'(안 딴 사람 안 깎임).

### 6-6. Lecture (강의) — Phase 4

- **[범위 밖] 강의 파트너(캐릭터)**: 별도 설계 진행. (단 in-lecture AI 답을 파트너 페르소나로 말하게 하면 일관성↑ — 설계 시 고려.)
- **[확정] 강의 내 AI = 해당 강의 RAG Q&A**: 그 강의 자료로만 답하는 RAG. Gemini(요금 **Tier 1** 계정).
  - [제안] 모델은 **Flash급**(Pro ❌) — 300원/100질문=3원/질문 예산은 Flash라야 성립(Pro는 ~10배 초과).
  - [제안] 기존 벡터 인프라 재사용(pgvector+gemini-embedding-001+match RPC). 검색은 **현재 강의로 스코프**.
  - [제안] 강의당 질문 **쿼터 서버측 카운팅**(비용 폭발 방지) + 타이트한 시스템 프롬프트(인젝션/오프토픽 차단).
- **[확정] 마이페이지 AI = 학습 지원**: 사용자 데이터(레벨·6축·약점·이력) 기반 학습 조언·추천.
  - [제안] 이건 **문서 RAG가 아니라 구조화 데이터→프롬프트→조언**이 맞음(벡터 오버엔지 금지). 콘텐츠 추천까지면 카탈로그 임베딩 결합.
- **[확정(방향)] 비용**: 1강의 ~300원 = **AI 원가 추정치**(유저 가격 아님). Flash면 오히려 낮을 수(~100원/100질문). **[검토중]** 유저 과금 방식(강의 구매 번들 vs 별도 크레딧)은 강의 유·무료 정책과 함께 나중.

## 7. 현재 코드베이스와의 갭 (2026-07-13 기준)
