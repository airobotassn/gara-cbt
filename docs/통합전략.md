# GARA 통합 전략 — 레벨테스트 × CARIS CBT

> 목적: 지금 **두 개로 갈라진** 서비스(무료 레벨테스트 / 유료 CARIS 자격검정)를
> **레포 1 · Supabase 1 · Cloudflare 1**로 통합한다. 이 문서는 실행 로드맵이자 결정 기록이다.

---

## 0. 확정된 방향 (결정 완료)

| 항목 | 결정 |
|---|---|
| **제품 모델** | 무료 **레벨테스트 = 퍼널** → 유료 **CARIS 자격검정 = 인증**. 한 사이트·한 계정에서 자연스럽게 이어짐. |
| **코드 아키텍처** | **단일 Vite 앱 + 라우트 네임스페이스** (`/test/*` = 레벨테스트, `/exam/*` = CBT). Layout·i18n·auth·디자인 공유. |
| **데이터** | 양쪽 다 **런칭 전, 실데이터 없음** → 보존 제약 없음. 스키마를 깔끔하게 재설계 가능. |
| **베이스 트렁크** | **`ai-level-test`** 를 베이스로, CBT를 그 위에 이식 (아래 §1 근거). |

## 1. 왜 ai-level-test가 베이스인가

- `gara-cbt`는 **`ai-level-test`에서 포크된 것** (`package-lock.json`에 아직 `"name": "ai-level-test"` 잔존).
- 포크 후 gara-cbt는 레벨테스트 엔진(티어·6축 레이더·EWMA·랭킹·리커멘드)을 **삭제**하고 CARIS 시험 흐름을 **추가**했다.
- 따라서 통합은 방향에 따라 난이도가 크게 다르다:
  - **A. ai-level-test 베이스 (채택)** — 복잡한 레벨테스트 엔진은 **그대로 보존**, CBT는 이미 네임스페이싱된 **추가형(Exam*, `/exam/*`)** 이라 위에 얹기만 하면 됨.
  - B. gara-cbt 베이스 — 삭제됐던 레벨테스트 엔진 전체를 **되살려 이식**해야 함 → 재구성 리스크 큼.
- gara-cbt의 자산(최신 디자인 `DESIGN.md` "GARA Precision", 폰트 Hanken Grotesk+Pretendard, CARIS 페이지들, `caris.ts`)은 **추가형이라 그대로 이식** 가능.
- **결론**: 큰 엔진(레벨테스트)은 보존, 작은 추가분(CBT)만 옮긴다 = 손실·리스크 최소.

## 2. 최종 타깃 구조

### 2.1 레포 / 도메인 / 워커
- **레포**: `ai-level-test`(원격 `airobotassn/gara_home`)를 트렁크로 유지. 통합 완료 후 `gara-cbt` 레포는 **아카이브**.
- **워커**: 단일 워커(현 `gara-leveltest` 유지 또는 `gara`로 리네임). `gara-cbt` 워커는 은퇴.
- **도메인**: 하나로 통일(현 `gara-home.airobotassn.workers.dev` 유지 또는 커스텀 도메인 지정). GitHub `master` push → Cloudflare 자동배포.

### 2.2 라우트 네임스페이스 (단일 앱)
```
/                     통합 랜딩 (무료 레벨테스트 CTA + 유료 CARIS CTA + 검색추천)
/login  /auth/callback   공용 인증

/test/select          레벨테스트 난이도 선택
/test/:attemptId      레벨테스트 진행
/test/result/:id      레벨테스트 결과(티어·레이더)
/ranking  /dashboard  리더보드 · 학습 대시보드

/exam                 CARIS 응시 게이트(SEB 체크)
/exam/schedule /apply /check /prepare   원서접수·사전점검
/exam/run/:attemptId  CBT 시험(SEB·OMR·타이머)
/exam/result/:id  /exam/done            결과·SEB 종료
/certificate  /guide  /notice  /faq     자격증·안내

/mypage               통합 마이페이지(레벨 이력 + 응시/자격 탭)
/admin                통합 관리자
/about /privacy /terms
```

### 2.3 통합 Supabase 스키마 (네임스페이싱)
> **핵심 리스크 = 두 프로젝트가 `questions`·`attempt_answers`를 서로 다른 모양으로 공유.**
> 베이스(레벨테스트)는 이름 유지, **CBT 쪽 충돌 테이블만 리네임**한다.

| 구분 | 테이블 | 비고 |
|---|---|---|
| **공용(계정)** | `profiles`, `admin_users` | 레벨테스트 것 유지(더 리치). 두 서비스 공통 계정. |
| **레벨테스트(유지)** | `questions`, `test_attempts`, `attempt_answers`, `user_level_skill`, `user_progress`, `question_reports`, `reco_cache`, `reco_shadow_log` | 이름·스키마 그대로. |
| **CBT(이식+리네임)** | `exams`, **`exam_questions`**(←`questions`), `exam_attempts`, **`exam_answers`**(←`attempt_answers`) | 충돌 2개만 리네임. `exams`·`exam_attempts`는 충돌 없어 그대로. |

RLS 원칙 동일: 민감 테이블은 **service-role 전용**(클라 직접 SELECT 금지), 출제·채점·결과는 **Edge Function에서만**.

### 2.4 통합 Edge Functions (한 프로젝트로)
- **레벨테스트 유지**: `start-test`, `submit-test`, `get-result`, `list-attempts`, `recommend-level`, `leaderboard`, `submit-report`, `translate-questions`, `kb-*`, `admin`
- **CBT 이식**: `start-exam`, `submit-exam`, `get-exam-result`, `my-attempts` (새 테이블명 반영)
- **`_shared`**: 레벨테스트 `lib.ts`(스코어링·인증)·`cors.ts` 유지 + CBT `seb.ts` 추가
- **admin 병합**: 두 admin 로직을 하나로(시험 관리 + 레벨 관리). `admin_users` allowlist·ROOT_ADMIN 상수 통일.

## 3. 단계별 실행 순서

> 각 단계는 커밋 단위로 끊어 검증. Supabase/Cloudflare 전환은 마지막에 몰아서.

- **Phase 0 — 준비**: ai-level-test·gara-cbt 현재 상태 git 태그로 스냅샷. 통합 Supabase = 레벨테스트 프로젝트(`jfvldoywvzvqhitcgalr`) 재사용(OAuth·Storage·Gemini 시크릿 이미 세팅됨). gara-cbt 목업 데이터는 폐기 OK.
- **Phase 1 — 통합 스키마**: 레벨테스트 `schema.sql`에 CBT 테이블(`exams`·`exam_questions`·`exam_attempts`·`exam_answers`) 추가 + RLS. 마이그레이션 작성·적용.
- **Phase 2 — 함수 이식**: CBT 4개 함수 + `seb.ts`를 레벨테스트 프로젝트로 복사, 새 테이블명 반영, `admin`/`_shared` 병합, **CLI로 배포**.
- **Phase 3 — 프론트 이식**: CBT 페이지(`Exam*`·`Certificate`·`Guide`·`Notice`·`Faq`·`MyPage`·`Login`)·`caris.ts`를 ai-level-test로 복사, `App.tsx` 라우터를 `/exam/*` 네임스페이스로 병합. `callFunction` 재사용.
- **Phase 4 — 셸 통일**: 통합 랜딩(무료 레벨테스트 CTA는 **내부 `/test`**, 유료 CARIS는 `/exam`), Layout·nav·FAB·언어선택 병합, `LEVELTEST_URL` 외부 링크 제거.
- **Phase 5 — 디자인 통일**: GARA Precision(`DESIGN.md`) + 폰트 채택, 레벨테스트 페이지 스타일을 통일 톤으로 정리.
- **Phase 6 — i18n·문서·설정**: i18n 사전 6개국어 병합, `CLAUDE.md`/`README`/온보딩을 **통합본**으로 개편, env·함수 시크릿 통합, `wrangler` 워커명 확정.
- **Phase 7 — 배포 전환**: 통합 워커 배포 + 도메인 지정 + 함수 CLI 배포. `gara-cbt` 워커/레포 아카이브. 스모크: 게스트 레벨테스트 → 로그인 이관 → CARIS 원서접수(목업).

## 4. 리스크 & 주의

- **테이블명 충돌**(최대 리스크) → CBT 쪽 `questions`→`exam_questions`, `attempt_answers`→`exam_answers` 리네임으로 해소.
- **계정 통합**: 두 Auth 풀을 레벨테스트 풀 하나로 합침(실데이터 없어 안전). 도메인 바뀌면 **Supabase Auth Site URL/OAuth redirect** 갱신 필수.
- **스코어링 sync 가드**: 레벨테스트 `scoring.ts` ↔ `_shared/lib.ts`의 `<scoring-sync>` 규칙 유지(둘 다 고칠 것). CBT 채점은 별개 경로.
- **admin/_shared 병합**: 권한 로직·allowlist·ROOT_ADMIN 재확인.
- **결제·본인인증 미구현**: `ExamApply` 결제는 아직 목업 → 통합과 **별개로 남는 유료 전환 과제**. 퍼널의 "유료" 끝단은 실제 구현 필요.
- **함수 배포**: `_shared` import 함수는 **CLI로만** 안전 배포(대시보드 웹에디터 금지). git push로는 함수 안 올라감.
- **디자인/폰트 충돌**: Tailwind v4 토큰·폰트를 Phase 5에서 일원화.
