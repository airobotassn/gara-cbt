# GARA 통합 전략 — CARIS CBT(메인) × 레벨테스트(모듈)

> 목적: 지금 **두 개로 갈라진** 서비스를 **레포 1 · Supabase 1 · Cloudflare 1**로 통합한다.
> **CBT가 메인 홈**이고, 레벨테스트는 그 안의 **무료 진단 모듈**(`/test/*`)로 들어온다.
> 이 문서는 실행 로드맵이자 결정 기록이다.

---

## 0. 확정된 방향

| 항목 | 결정 |
|---|---|
| **제품 모델** | **CBT(CARIS 자격검정)가 메인**, 레벨테스트는 무료 진단 퍼널. 한 사이트·한 계정. |
| **코드 아키텍처** | **단일 Vite 앱 + 라우트 네임스페이스** (`/exam/*` = CBT, `/test/*` = 레벨테스트). 한 도메인·한 워커·한 로그인. |
| **데이터** | 양쪽 다 **런칭 전, 실데이터 없음** → 스키마 깔끔히 재설계 가능. |
| **베이스 트렁크** | **`gara-cbt`** (CBT가 홈·셸·디자인·마이페이지). 레벨테스트 엔진을 ai-level-test에서 **복사해 이식**. **ai-level-test 레포/워커는 삭제·아카이브 없이 그대로 보존**(복사 원본 겸 요구사항 변동 대비 백업). |

### 왜 gara-cbt가 베이스인가 (베이스 뒤집음)
- 최종 제품의 **얼굴이 CBT** — 메인 홈·마이페이지·FAB·디자인(GARA Precision)·현재 작업 트리가 전부 gara-cbt.
- 레벨테스트는 랜딩을 버리고 **기능 페이지만**(`/test/select`·진행·결과·랭킹) 모듈로 들어옴 → 이식 대상이 작고 자기완결적.
- 두 모듈 다 ai-level-test / gara-cbt에 **온전히 존재**하므로 "복원"이 아니라 **파일 복사 + 라우트/테이블명 배선**만 하면 됨. 복잡한 스코어링 로직은 파일째 그대로 옮겨 보존.

## 1. 통합 정보구조 (IA) — 확정

- **`/` = CBT 메인 홈.** 레벨테스트 랜딩 페이지는 **폐기**.
- 레벨테스트 랜딩의 **검색창(Gemini 레벨 추천)** → **CBT 홈**으로 이동(홈 기능으로 편입).
- 레벨테스트 **학습 대시보드**(레이더·응시이력·기여그래프) → **CBT 마이페이지** 안의 탭/섹션으로 흡수.
- CBT 홈의 **"무료 레벨 진단"** 버튼 + CBT **FAB의 레벨테스트** → 앱 내부에서 **`/test/select`** 로 이동(외부 URL 아님).
- 레벨테스트 영역 안에 **랭킹 페이지(`/ranking`)로 가는 버튼** 배치(헤더/네비 등).
- **관리자 통합**하되 **레벨테스트 / CARIS 시험 섹션을 탭으로 구분**.

### 라우트 맵
```
/                     CBT 메인 홈 (레벨 추천 검색창 포함, 무료 진단 CTA)
/login  /auth/callback   공용 인증(한 계정)

/exam                 CARIS 응시 게이트(SEB 체크)
/exam/schedule /apply /check /prepare   원서접수·사전점검
/exam/run/:attemptId  CBT 시험(SEB·OMR·타이머)
/exam/result/:id  /exam/done            결과·SEB 종료
/certificate  /guide  /notice  /faq     자격증·안내

/test/select          레벨테스트 진입점(랜딩 없이 바로 여기)
/test/:attemptId      레벨테스트 진행
/test/result/:id      레벨테스트 결과(티어·레이더)
/ranking              리더보드 (레벨테스트 영역에서 버튼으로 진입)

/mypage               통합 마이페이지 = CBT 응시/자격 + 레벨 학습 대시보드(탭)
/admin                통합 관리자 (탭: CARIS 시험 / 레벨테스트)
/about /privacy /terms
```

## 2. 서브시스템 통합 설계

### 2.1 레포 / 도메인 / 워커
- **레포**: `gara-cbt`가 트렁크. 레벨테스트 엔진을 **복사**해 이식. ai-level-test 레포는 **그대로 보존**(삭제/아카이브 안 함) — 복사 원본 겸 요구사항 변동 대비 백업.
- **워커**: 단일 워커(현 `gara-cbt` 유지 또는 통합명으로 리네임). `gara-leveltest` 워커는 **당분간 그대로 유지**(안정화 확인 후 은퇴 재검토).
- **도메인**: 하나로 통일. `master` push → Cloudflare 자동배포. SPA 라우팅은 `wrangler.jsonc`(`not_found_handling`).

### 2.2 통합 Supabase 스키마 (네임스페이싱)
> **핵심 리스크 = 두 프로젝트가 `questions`·`attempt_answers`를 서로 다른 모양으로 공유.**
> 베이스(CBT)는 이름 유지, **이식되는 레벨테스트 쪽 충돌 테이블만 리네임**한다.

| 구분 | 테이블 | 비고 |
|---|---|---|
| **공용(계정)** | `profiles`, `admin_users` | 두 서비스 공통 계정. 컬럼 병합(레벨테스트의 `is_anonymous` 등 흡수). |
| **CBT(유지)** | `exams`, `questions`, `exam_attempts`, `attempt_answers` | 이름 그대로. `questions`=시험 문제, `attempt_answers`=시험 답안. |
| **레벨테스트(이식+리네임)** | **`test_questions`**(←`questions`), `test_attempts`, **`test_answers`**(←`attempt_answers`), `user_level_skill`, `user_progress`, `question_reports`, `reco_cache`, `reco_shadow_log` | 충돌 2개만 리네임. 나머지는 충돌 없어 그대로. |

RLS 원칙 동일: 민감 테이블은 **service-role 전용**, 출제·채점·결과는 **Edge Function에서만**.

### 2.3 통합 Edge Functions
- **CBT 유지**: `start-exam`, `submit-exam`, `get-exam-result`, `my-attempts`, `admin`, `seed-demo`
- **레벨테스트 이식**: `start-test`, `submit-test`, `get-result`, `list-attempts`, `recommend-level`, `leaderboard`, `submit-report` (그리고 필요 시 `kb-*`·`translate-questions`)
- **`_shared`**: CBT `lib.ts`·`cors.ts`·`seb.ts` 유지 + 레벨테스트 스코어링 로직을 **별도 `_shared/scoring.ts`** 로 이식.
  - `<scoring-sync>` 페어는 이제 **`src/lib/scoring.ts` ↔ `supabase/functions/_shared/scoring.ts`** (둘 다 같이 고칠 것).
- **admin 병합**: CBT `admin` 함수에 레벨테스트 관리 오퍼레이션을 섹션으로 추가(또는 `admin` + `admin-test` 분리 후 한 화면 탭). `admin_users` allowlist·ROOT_ADMIN 통일.
- **이식 함수는 새 테이블명**(`test_questions`·`test_answers`)으로 쿼리 수정 필요.

### 2.4 프론트 이식 대상 (ai-level-test → gara-cbt)
- **페이지**: `LevelSelect`→`/test/select`, `TestRunner`→`/test/:id`, `Result`→`/test/result/:id`, `Ranking`→`/ranking`. (`Landing`·`Dashboard`는 페이지째 이식하지 않고 **홈/마이페이지로 흡수**.)
- **컴포넌트**: `TierEmblem`, `RadarChartBox`, `LineChart`, `ContributionGraph`, `useCountUp`, `useAntiCheat`(중복 시 병합).
- **lib**: `scoring.ts`, `categories.ts`, `testConfig`(병합), `avatar`(중복 확인), i18n 레벨 문자열 6개국어 병합.
- **홈 편입**: 레벨 추천 **검색창** UI + `recommend-level` 호출을 CBT `Landing`에 이식. 결과(추천 레벨)는 `/test/select` 진입 또는 CARIS 등급 안내로 연결.
- **마이페이지 편입**: 대시보드의 레이더/이력/기여그래프를 `MyPage` 탭으로.

## 3. 단계별 실행 순서

- **Phase 0 — 준비**: 양 레포 현재 상태 git 태그 스냅샷. 통합 Supabase = **CBT 프로젝트(`lditytpxuuojfznwfnep`) 재사용** 또는 신규(§5 결정). `ExamApply.tsx` 미커밋 변경 먼저 정리.
- **Phase 1 — 통합 스키마**: CBT `schema.sql`에 레벨테스트 테이블(`test_questions`·`test_attempts`·`test_answers`·`user_level_skill`·`user_progress`·`question_reports`·`reco_cache`·`reco_shadow_log`) 추가 + RLS. `profiles`/`admin_users` 컬럼 병합. 마이그레이션 작성·적용.
- **Phase 2 — 함수 이식**: 레벨테스트 함수 7종 + `_shared/scoring.ts`를 CBT 프로젝트로 복사, 새 테이블명 반영, `admin`/`_shared` 병합, `GEMINI_API_KEY` 시크릿 설정, **CLI 배포**.
- **Phase 3 — 프론트 이식**: 레벨테스트 페이지/컴포넌트/lib를 gara-cbt로 복사, `App.tsx`에 `/test/*`·`/ranking` 라우트 추가, `callFunction` 재사용, i18n 병합.
- **Phase 4 — 셸 편입**: CBT 홈에 **레벨 추천 검색창** + "무료 레벨 진단" CTA(→`/test/select`), **FAB에 레벨테스트** 항목(→`/test/select`), 레벨테스트 영역에 **랭킹 버튼**, `MyPage`에 **학습 대시보드 탭**. 외부 `LEVELTEST_URL` 링크 제거.
- **Phase 5 — 관리자 통합**: `/admin`을 **탭(CARIS 시험 / 레벨테스트)** 으로. admin 함수·화면 병합, 섹션별 데이터 스코프.
- **Phase 6 — 디자인·i18n·문서**: 레벨테스트 페이지를 **GARA Precision**·폰트로 톤 통일. i18n 6개국어 최종 병합. `CLAUDE.md`/`README`/온보딩 통합본 개편. env·시크릿 통합.
- **Phase 7 — 배포 전환**: 통합 워커 배포 + 도메인 지정 + 함수 CLI 배포. **ai-level-test 워커/레포는 보존(은퇴 보류)**. 스모크: CBT 홈 → 무료 진단(`/test/select`) → 결과 → 랭킹 → 로그인 이관 → 원서접수(목업) → 마이페이지 대시보드.

## 4. 리스크 & 주의

- **테이블명 충돌**(최대 리스크) → 레벨테스트 `questions`→`test_questions`, `attempt_answers`→`test_answers` 리네임으로 해소.
- **계정 통합**: 두 Auth 풀을 하나로(실데이터 없어 안전). 도메인 확정 시 **Supabase Auth Site URL/OAuth redirect** 갱신.
- **스코어링 sync 가드**: 페어를 `src/lib/scoring.ts` ↔ `_shared/scoring.ts`로 재정의, 둘 다 같이 수정.
- **recommend-level 인프라**: Gemini 키·`reco_cache`(pgvector) 동반 이식. CBT에서 비활성이던 검색을 다시 켬.
- **admin 병합**: 권한 로직·allowlist·ROOT_ADMIN 재확인, 섹션별 데이터 격리.
- **결제·본인인증 미구현**: `ExamApply` 결제는 목업 → 통합과 **별개로 남는 유료 전환 과제**.
- **함수 배포**: `_shared` import 함수는 **CLI로만** 안전 배포. git push로는 함수 안 올라감.
- **디자인/폰트 충돌**: Tailwind v4 토큰·폰트를 Phase 6에서 일원화(GARA Precision 기준).

## 5. 실행 전 확정 권장

- 통합 워커/도메인 최종 이름 (현 `gara-cbt` 유지 vs 통합명 리네임 vs 커스텀 도메인).
- 통합 Supabase: **CBT 프로젝트 재사용**(권장, 베이스와 일치) vs 새 프로젝트 신설.
- 홈 검색창 결과의 착지점: `/test/select` 프리셋 진입 vs CARIS 등급 추천 안내 vs 둘 다.
- 마이페이지 탭 구성: (응시/자격) + (레벨 학습 대시보드) 배치 방식.
