# 문제 자동 생성 — 설계

문항을 **자료 수집 → 문제 생성 → 번역 → 발행**까지 자동으로 만드는 기능.
**두 개의 독립 기능**(사용자 관점): ① 자료(INPUT) / ② 문제 생성(OUTPUT). 서로 자동으로 안 이어진다.

> ★ 핵심 전제: **자료(청크)는 사람 검증 0** — 수백 개를 일일이 못 보니 자동 게이트(quote_ok·중복)에 맡긴다. **문제(문항)는 하네스가 주 방어** — 근거에 묶고 관문마다 할루시네이션을 막고, **사람은 그 위에 마지막 검수**(시험 그 자체라). 즉 *자료=자동 / 문제=하네스 + 사람 마지막 한 겹.*

---

## 큰 그림

```
[INPUT 자료]  AI 자동수집(cron) + 수동(URL·본문·파일)
                → 가져오기 → 추출(청크+토픽) → 자동필터(quote_ok+중복) → 저장(kb_chunks)
                → 갱신(토픽 diff로 분야 변화 추적)

[OUTPUT 생성]  (수동) 근거 꺼내기 → 문항 만들기 → 하네스(인용 실재·정답/오답 검증·lint)
                → 사람 검토 → 번역 → 발행 → (사후) 변별도/트라이얼 보조 그물
```
가로지르는 것: **프롬프트 관리자 편집** · **문제 유형(라벨)** · **비용/모델/리밋** · **저작권**.

# INPUT — 자료 (지식 저장소 채우기)

## 원칙
- 근거는 **사람도 LLM도 아닌 외부 실제 문서**에서. (지식을 지어내지 않음)
- 저장소는 죽은 스냅샷이 아니라 **스스로 채우고 최신 유지**(cron).
- **사람 검증 0** — 품질은 자동 게이트(quote_ok·중복)가 책임. 청크를 사람이 일일이 검토하는 화면 없음.

## 1. 자료가 들어오는 길 — 두 갈래
- **A. AI 자동 수집 (cron)** — 주된 경로. 시스템이 주기적으로 스스로 검색·수집. *사람 버튼 없음.*
- **B. 수동 입력** — URL · 본문 붙여넣기 · 파일. 사람이 가끔 특정 자료를 콕 넣을 때.

둘 다 같은 뒷단(가져오기→추출→필터→저장)으로 합류. 설계의 무게는 A에 있다.

## 2. AI 자동 수집(cron)의 행동
**① 무엇을 검색하나** — 처음엔 축이 넓으니 **LLM이 축을 구체 검색어로 펼침**(query expansion). 자료가 쌓여 **토픽(소분류)이 드러나면 그 토픽으로 정밀 검색** → 검색할수록 촘촘해짐. (이 토픽 목록 = 갱신이 감시하는 목록과 동일)

**② 어디부터 (우선순위)** — **자료/문항 적은 얇은 축부터** 채운다. (고정 목표치 숫자 없음. 비중·수요 같은 가중치는 군더더기라 안 씀 — 필요하면 나중에)

**③ 언제 멈추나 (백오프)** — **2번 연속, *매번 다른 검색어*로 긁었는데도 중복 90% 이상**이면 그 축 "마름"으로 보고 **중단(백오프=쉼, 영구정지 아님).**
- 한 번으로 판정 X(같은 검색이면 중복은 쉽게 떠서 못 믿음), *다양한 검색에서도* 다 중복일 때만.
- **재개**: 문제 생성 **수요**가 생기거나 **소스가 갱신(분야 변화)** 되면 다시 긁음.
- **출처 추적**: 가져온 URL 기록 → 갱신 전엔 재fetch 안 함(중복 작업 방지).

## 3. 뒷단 파이프라인 (A·B 공통)
- **가져오기(fetch)** — URL → 본문. 브라우저 UA·헤더로 봇차단 일부 회피. 강한 차단(Cloudflare 등)은 cron 경로에선 *건너뜀*, 수동 경로에선 *사람이 링크 열어 복붙.*
- **추출** — 본문 → 청크(지식 조각) + **축·토픽 태깅.** (청크는 임베딩 입력 2,048토큰 이내)
- **자동 필터 (사람 검증 X)**:
  - **quote_ok** — 청크가 원문에 실제로 있나(글자만 남겨 비교 + 80% 조각 매칭, 형식 차이 허용). 실패 → *자동 버림.*
  - **중복** — 같은 레벨 안 유사도 ≥0.92면 → *자동 버림.* (이 "버린 비율"이 곧 ③ 백오프의 마름 신호)
- **저장** — 통과한 청크만 임베딩과 함께 `kb_chunks`에 적재. 화면엔 **"저장 N · 버림 K" 요약 한 줄**만(편집/검토 UI 없음).

## 4. 갱신 — 분야 변화 따라가기 (토픽 diff)
"문서는 그대론데 **분야가 움직여 내용이 낡는 것**"(예: `프롬프트 엔지니어링이 가장 중요`의 비중 하락)을 잡는다. 단순 변경 감지로는 안 잡혀서, *세상이 어떻게 움직였나*를 다시 본다.

- **토픽 목록은 하나** — 수집(정밀 검색)과 갱신(diff)이 **같은 토픽 레코드를 공유**. 토픽마다 `[대표 임베딩 · 비중 · 마지막 본 시점 · 연속 결석]`. (신설 — 지금은 토픽이 청크 태그로만 흩어져 있음. 갱신 전용 아님, 공용)
- **한 달마다 6축 재검색** → 이번 회차 토픽 ↔ 저장 토픽을 **임베딩으로 매칭**:
  - 짝 있음 → 같은 토픽(이름만 바뀌어도 임베딩 가까우면 같은 것) → `마지막 본 시점`·`비중` 갱신, `결석=0`.
  - 짝 없는 새것 → **신규 토픽** 추가.
  - 저장됐는데 이번에 안 나옴 → `결석 +1`.
  - *회차 로그는 안 쌓음* — 과거 기억은 토픽마다 이 카운터들에 압축.
- **신규 토픽** → 그 축 **수집 재활성**(백오프 깨워서 cron이 새 자료 긁어옴).
- **old 토픽**(결석 K번 / 오래 안 나옴) → **죽이지 않는다**(틀린 게 아니라 덜 현행일 뿐 + 갱신 오판 가능). 대신 세 군데서 **"덜"**: 수집 덜 긁고 · 생성 덜 만들고 · 기존 문항은 두되 출제 우선순위만↓. → 새 토픽 문항이 늘며 비중 자연 재조정.
- ★ **낡음 ≠ 틀림**: 변별도는 *틀린 키*는 잡아도 *낡음*은 못 잡음(낡은 문항도 잘하는 사람은 맞힘). 그래서 **낡음 = 갱신(비중 조정) / 틀림 = 변별도·제보(OUTPUT 격리)** 로 분리.
- 비용: 본문 아니라 토픽 목록만 → 작음.

## 5. 저장소 구조
**분류 트리** `레벨 → 축(6) → 토픽(소분류)`. 저장소 하나(`kb_chunks`) = 임베딩 + 구조 태그.
- 트리 탐색 = 태그 필터, 의미검색 = 그 안 벡터검색. **중복검사·근거검색 모두 "노드로 좁히고 → 유사도"**(풀서치 X).

# OUTPUT — 문제 생성 (자료와 독립 기능)

## 0. 본질 = 할루시네이션 막는 하네스
INPUT/갱신이 *진짜 근거*를 깔아놨다. OUTPUT은 "문제를 빚는 것"이 아니라 **생성 LLM이 근거 밖으로 못 나가게 관문마다 가두는 하네스**다.

## 1. 트리거 = 수동 (자료는 자동, 문제는 사람 영역)
관리자가 "이 축에 몇 개" 돌린다. **cron 자동 생성 X.** 자료(청크)는 중간 재료라 자동·검증0이지만, **문제는 최종 산출물(시험)** 이라 어떤 걸 어떻게 넣을지 사람이 본다.

## 2. 근거 꺼내기 (요청: L1 보안 8문항)
- **토픽별로 묶어 두 숫자를 본다** — `[가진 청크 수]` + `[기존 활성 문항 수]`.
- **빈 문항 토픽부터 배정**("골고루"=균등 X, 문제은행 *구멍 메우기*) + **청크 수로 상한**(청크 적으면 많이 못 냄). 예) 탈옥(문항0)·모델추출(0) → 프롬프트인젝션(1) → 데이터유출(3) 순으로 8개 분산.
- **빈 노드(청크 0)** = 생성 시도 안 함 + **"비었음"을 수집 신호**로(채워라).
- **문항당 청크 1개(소수)** — 정답을 *그 한 청크에 대고* 검증(③)하려고. 맥락 필요하면 옆 청크만 보조.
- **중복 회피** = **출제 포인트 임베딩**(문제 텍스트 X)으로 그 토픽 기존 문항과 비교. 확실 중복=스킵 / 확실 다름=통과 / **회색지대 = LLM 안 씀 → 검토 화면에 "기존 ○○과 비슷할 수 있음" 플래그 → 사람 판단**(어차피 검토하니 공짜).

## 3. 하네스 — 생성 문항이 통과할 관문
| 관문 | 막는 것 | AI |
|---|---|---|
| ① 근거 가두기 — 청크 하나만, 밖 지식 금지 | 지어낼 재료 | (생성) |
| ② 정답=근거 + 인용 강제 | 근거 없는 정답 | (생성) |
| **③ ★ 인용 실재 검사(기계)** — 인용이 진짜 청크에 있나 글자 대조 | **정답 할루시네이션(핵심)** | ❌ 공짜 |
| ④ 정답 뒷받침 검사(AI 독립) — 인용이 정답 받치나 | 장식 인용 | ✅ |
| ⑤ 오답 검증 — 오답 3개 진짜 다 틀림 | 정답 둘 | ✅ |
| ⑥ 문항 lint(규칙) — item-writing 표준 | 품질 결함 | ❌ 공짜 |
| ⑦ 저작권 lint — near-verbatim 컷 | 원문 베끼기 | ❌ 공짜 |
| ⑧ 경계 lint — 주관·충돌·빈노드 | 근거가 답 못 줌 | (아래) |

- **③④⑤는 한 검증 콜로** 묶음(③ 기계 공짜, ④⑤만 AI=1콜).

## ⑧ 경계 — 별도 탐지기 아님
- **빈 노드** = 기계 자동 제외 + 수집 신호.
- **주관·논쟁 / 출처 충돌** = ④⑤ 검증이 *"근거 약함 / 오답 불명확"* 으로 자연히 드러냄 → 자동 통과 X → **사람 검토로 라우팅**(사람이 공정하면 두고 아니면 버림). 사람 검토가 "마지막 한 겹"인 이유가 여기.

## 4. AI 리밋 — 병목 아님
묶음 생성(8~10/콜) + 검증 1콜 = **묶음당 요청 2개**, 검증은 싼 모델. 한도(무료 ≈15 RPM/500 RPD, 확정은 대시보드)여도 *하루 ~2,000문항* → 수동+묶음엔 충분.

## 5. 품질 체크 = 확립된 표준
⑥ 문항 lint = **Haladyna(31지침)·NBME(item flaws)** 를 코드로. 상당수 규칙 기반(공짜): "모두/없음" 금지·부정형 강조·보기 길이균형·문법 단서·절대어·보기 중복·단서 누출. 의미 판단(보기 동질성·오답 틀림)만 AI(검증 콜에 묶음).

## 6. 사람 검토·승인 = 마지막 한 겹
하네스(①~⑧)가 다 거른 *위에* 얹는다. 의심 플래그(정답 의심·약한 근거·중복 회색지대) 단 것에 집중. 수정/반려/승인 → 발행. **주된 방어는 하네스, 사람은 안전핀.**

## 7. 사후 안전망 (보조 — 사람도 놓치니까)
발행 후에도 도는 그물:
- **변별도** — 잘하는 사람이 틀리면 정답키 오류(음수). 자동·사용자 협조 0. (*틀림*만 잡고 *낡음*은 갱신 담당)
- **제보** — 기존 `question_reports`. 보너스(의존 X).
- **트라이얼 채점** — 신규 문항 처음 M회 점수 미반영 → 불량이 등급 망치기 전에 걸러짐.

## 8. 번역 → 발행
승인 문항 → 기존 `translate-questions → upsert` 재사용.

# 프롬프트 관리자 편집 (레벨별 출제 지침)
- **두 층**: ① 🔒 **시스템 규칙(개발자·고정)** = 근거가두기·정답인용·출력형식·안전장치(`kb-generate`의 `SYSTEM_RULES`, **UI 비노출·수정불가** — 하네스가 돌려면 고정). ② **레벨별 출제 지침(관리자·편집)** = *이 레벨은 어떤 난이도로, 뭐가 중점인지*.
- **레벨이 단위**: 생성 탭에서 Lv.N 고르면 그 레벨 지침이 뜸 → 블록(한 줄=한 지침)으로 추가/수정/순서/삭제. 레벨마다 따로 저장(현재 `localStorage` `gen_level_guidance_v1`, 초기 7개 레벨 기본값 시드). 생성 시 `levelGuidance: guide[level]` 로 전송, 함수가 시스템 규칙 **뒤에 덧붙임**(덮지 못함).
- 안전 = "AI가 안 보게"가 아니라 **"검사로 잡아서"** — 지침은 세게 먹히되, 형식·정답근거·안전은 생성 후 하네스(①~⑧)가 강제.

# 비용 · 모델 · 리밋
- **cold start(초기 벌크)** = 정액 **구독 모델**(종량 X). **임베딩** = Batch API. **평상시** = 종량 Gemini + 스로틀.
- 키 분리(생성/번역). 리밋: 무료 flash-lite ≈15 RPM/~1,000 RPD, 유료 Tier1 ≈300 RPM(AI Studio 대시보드 확인). 임베딩 입력 2,048토큰/건.

# 저작권 / ToS
**사실은 가져오되 표현은 안 베낀다.** 생성 문항=새 표현+near-verbatim 컷 / 원본=내부 비공개(응시자 노출 X) / 인용=짧게 내부용 / 출처=자유 라이선스 위주(Wikipedia·공식·표준) / 이미지 안 가져옴.

# 확정 정책값 (값만, 추후 조정)
- 백오프: **2회 연속(다른 검색어) 중복 ≥90%** → 마름.
- 중복 임계값: **0.92**.
- 수집 우선순위: **얇은 축부터**(가중치 없음).
- 갱신 주기: 한 달급(토픽 diff).
- 트라이얼 노출 M회 / 제보 N건 임계: 데이터 보며 조정.

# 핵심 설계 결정 로그
- 자료 수집: ~~사람이 AI추천 버튼~~ → **cron 자동 수집**(얇은 축 우선 + 백오프).
- 사람 게이트: ~~청크 검토 + 모두 자동발행~~ → **자료=사람 검증 0(자동 필터)** / **문제=하네스 주 방어 + 사람 마지막 검수**(생성은 수동). 사후 변별도/트라이얼은 보조 그물.
- 수집량: ~~고정 목표치 숫자~~ → **마를 때까지(백오프)** = 자료 양에 자동 적응.
- 저장 단위: ~~사실 한 줄~~ → **원본 통째 + 청크 색인**(문제화는 생성 때).
- 갱신: ~~해시 변경 감지~~ → **토픽 diff(분야 드리프트)**.

# 구현 상태
- **됨**: 수동 입력(URL·파일·본문) · 추출+토픽태깅 · quote_ok(느슨) · 중복검사 · 저장+임베딩 · 생성 초안+하네스(lint⑥⑦⑧·AI검증④⑤) · **레벨별 출제 지침 편집(시스템 규칙 고정)** · 사람 검수 후 **번역·발행**(`kb-publish`→`questions`). (`kb-extract`·`kb-save`·`kb-generate`·`kb-publish`·`kb_chunks`·`tools/index.html`)
- **콜드스타트 적재 완료(무료·생성LLM 없이 · 큐레이션판)**: 위키피디아 ~78문서를 **문단 단위로 에이전트가 직접 선별**(연표·일화·버전사·마케팅 등 잡음 버리고 알짜만) → `kb-save`(`embed:false`, 본문만). 도구 `tools/curate.mjs`(`list`로 후보 출력 → `save`로 번호 선택; **원문 인덱스 선택이라 텍스트 변형 0** = 할루시네이션 안전). **42/42셀 · 약 1,965청크**(레벨당 200~360, 최소 셀 15). Gemini 호출 0(생성은 레벨/축으로 청크를 뽑으니 임베딩 없이 동작). 재실행 안전(레벨 내 동일본문 skip). 기계적 1차분(`coldstart.mjs`)은 잡음이 섞여 폐기·교체.
- **응용 출처 보강(Wikibooks)**: 위키피디아(백과사전=사실→암기형)만으론 기술축이 약해서, **Wikibooks/Wikiversity**(튜토리얼·실습서=응용)를 추가 적재. `curate.mjs`가 멀티사이트+`search` 지원(`search/list/save <site>`, site=en.wikibooks 등). 기술축에 ~872청크 추가 → **총 ~2,832청크**(Lv2~4·6 대폭 증가). 임베디드/RTOS/인터럽트·PLC 스캔사이클·시리얼/UART·C/파이썬 의미론·로봇제어·CPS보안 등 **how-to 자료**.
- **🐞 생성 선택 버그 수정(중요)**: `kb-generate` 가 `.limit(count*3)`만 써서 **"처음 적재된 ~12개"만** 뽑혔다(나중에 넣은 응용 자료가 영영 안 뽑힘 + 매번 같은 문제). → RPC `random_kb_chunks`(ORDER BY random())로 교체. 이제 셀 전체에서 무작위로 뽑혀 **응용 자료도 닿고 변별/다양성도 생김**. (실측: STM32 셀이 "Cortex-M 기반" 암기 → "PI vs PID 언제 쓰나" 응용으로 바뀜)
  - **남은 것**: ① 임베딩 백필 — 함수·구동기 준비 완료(`kb-embed-backfill` + `tools/backfill.mjs`). 무료론 ~100개/버스트만 되니 **빌링/회복 후 한 방**. ② 문제 **벌크 생성**도 flash 할당량 필요(소량은 지금도 됨) → 빌링/리셋. ③ Lv5(엣지·IIoT·디지털트윈) 등 Wikibooks 빈약 축은 개념판 유지(필요시 추가 출처).
- **안 됨(설계만)**: AI 자동수집 cron · 토픽 되먹임 검색 · 백오프 · 갱신(토픽 diff) · 변별도/제보/트라이얼.
